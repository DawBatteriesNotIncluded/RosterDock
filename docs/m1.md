# Milestone 1: one agent works

Status as of 2026-09-12. The plan defines M1 as: queue, run records, run-scoped tokens; a worker
image that claims a run, checks out a worktree, runs Claude Code headless with the persona pack,
streams events, captures artifacts and the diff, reports usage; a reaper that requeues dead runs;
the task drawer showing the live log, outputs and tokens; budgets with 80% and 100% alerts and a
per-run cost line; basic sandbox presets and crash checkpoints. Demo: assign a task to Cody, watch
the run, open the produced files. Done when killing the worker mid-run requeues the task without
manual cleanup.

## How a run works

1. A person or teammate starts the assignee on a task. The board checks the assignee is a teammate,
   no other run is live, dependencies are done, the engine is enabled and no applicable budget is
   spent. The task moves to In progress and a job goes on the queue.
2. A worker takes the job, claims the run with the fleet token, receives the rendered pack and a
   token scoped to that run, and creates an ephemeral directory (cloning the project repository when
   one is set).
3. The engine runs headless with the pack as its whole prompt. The worker ships its log to the board
   in batches, heartbeats every 15 s, and stops the engine if the board asks.
4. When the engine ends, the worker collects the declared outputs (or, if none were declared, every
   new file), `handover-summary.md`, `blocked.md`, and the git diff, posts them as artifacts, saves a
   checkpoint, and reports completion with usage. The board prices the run, records usage, checks
   budgets, revokes the token and moves the task: review on success, Blocked with the reason on
   failure or a declared block, To do on stop.

## The done criterion

Killing the worker mid-run: the board sees the heartbeat go stale (60 s) and marks the run
interrupted; pg-boss sees the job heartbeat go stale (30 s) and retries the job after 60 s; a live
worker claims the interrupted run as attempt 2 with the checkpoint in its pack. A worker that
arrives before the board considers the run stale gets a 409 and leaves the job for a later retry;
a job pg-boss finally gives up on fails the run and blocks the task with `retries_exhausted`.
Verified live on 2026-09-12 with the stub engine: see the run log of the "worker killed mid-run"
task.

## Demo script

```bash
pnpm db:migrate && pnpm dev            # board + web
pnpm dev:worker                        # in a second terminal; engines: stub, claude_code
```

1. Hire a teammate on the `stub` engine (no model needed) or on Claude Code with `claude login` done.
2. Create a task assigned to them with expected outputs, e.g. `vms-architecture.md`.
3. In the drawer, Run tab, press Start. Watch the log, tokens and time; the Outputs tab shows the files.
4. Kill the worker process mid-run (a `[stub:hang]` marker in the task brief keeps the stub busy).
   Within about two minutes the run shows Interrupted, then a restarted worker resumes it as attempt 2.
5. Settings, budgets: set a company budget lower than the usage so far and try to start another run.

## Decisions taken while building

- Engines are rows in `engines`; teammates reference them by foreign key. `stub` exists so demos, CI
  and tests never need a model.
- The claim is the authority on staleness, not the reaper, so takeover does not depend on timer
  order. pg-boss retry delays are longer than the board's stale window for the same reason.
- Worker credentials: the fleet token claims; the run token does everything else and dies with the
  run. Engine credentials are env var names resolved in the worker only.
- Artifacts up to 512 KB are stored inline in Postgres. Object storage (MinIO) is wired in Compose
  and the chart but not used yet; larger artifacts are refused with 413 until it is (M2).
- The Claude Code adapter runs `--output-format stream-json` so the task drawer shows tool calls as
  they happen. Tool results and file contents never leave the sandbox as events.
- Both Claude Code stream fixtures are real recordings (an expired-session error and a haiku success run).
  `apps/worker/scripts/record-claude-fixture.mjs` re-records the success one after `claude login`.
- A real Claude Code run through the board (haiku, two files) took 16 s and 80k tokens, of which about
  70k were cache reads and 9k cache writes of the CLI system prompt and pack. Per-run cost is dominated
  by that fixed overhead; budgets and the price table account for cache classes separately.

## Not in M1 (by design)

- Object storage for large artifacts, Codex and OpenCode adapters, the Costs page and trend charts (M2).
- Sandbox network policies (M6). Filesystem isolation is the ephemeral directory and the tool allowlist;
  environment isolation is the allowlist of env names, narrowed per department.
